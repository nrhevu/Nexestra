# ADR 0072: Stop normal agent runs from the conversation

## Status

Accepted

## Context

Taskboard already stopped delegated Worker assignments, but ordinary mentioned agent runs could
remain active while a provider streamed, waited for approval, or retried a request. That left the
user without a local control to stop an unexpectedly expensive or stuck response.

## Decision

Every normally queued chat run receives an in-memory `AbortController`. The conversation exposes a
guarded `POST /api/runs/:id/stop` action for active non-assignment runs. The dispatcher aborts the
provider or CLI invocation, resolves that run's pending approvals and questions, persists the
stable user-facing interruption reason, and skips automatic retry. Assignment IDs remain owned by
Taskboard so stopping them also repairs worktree and task state.

The interrupted run remains in the canonical JSONL history and can be retried through the existing
retry action. No transcript content is generated by a stop request, and the endpoint only accepts
the opaque active run ID.

## Consequences

Custom provider requests now combine the run signal with their bounded request timeout, so stopping
works during network waits as well as CLI execution. A provider that ignores cancellation is still
prevented from writing a reply after the signal is observed. The stop control is hidden for archived
threads and delegated assignments, preserving their existing lifecycle boundary.
